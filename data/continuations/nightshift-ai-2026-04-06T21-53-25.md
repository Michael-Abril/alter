# NightShift AI - MVP Architecture Plan

Based on your context, here's the focused MVP architecture for your four-person team to build email and document continuation features in one month:

## Core MVP Scope (Month 1)
**Single Use Case:** Email drafting continuation
- User connects Gmail via OAuth
- Uploads chat history (Claude exports) 
- NightShift detects half-written email drafts
- User selects which drafts to continue overnight
- AI completes drafts in user's voice/style
- Morning review dashboard shows completed drafts

## Team Architecture (4 People, 4 Weeks)

### Week 1: Foundation (All 4 Together)
**Person 1 (Lead):** Gmail OAuth integration
**Everyone helps:** Database schema, user auth flow, file parsing
**Deliverable:** User can connect Gmail, upload chat history, both stored in PostgreSQL

### Week 2: Core Pipeline (Split into Pairs)
**Pair A (Person 1 + 2):** 
- Email draft detection in Gmail
- Context embedding pipeline (Pinecone)
- Chat history processing for style learning

**Pair B (Person 3 + 4):**
- Frontend dashboard (Next.js)
- Draft selection interface
- Basic continuation engine (Claude API)

### Week 3: Integration & Intelligence
**Person 1:** Draft completion logic with context retrieval
**Person 2:** Style matching using embeddings
**Person 3:** Review interface with approve/reject
**Person 4:** Morning brief generation

### Week 4: Polish & Deploy
**All:** Bug fixes, edge cases, deployment pipeline

## Technical Stack (Simplified)
```
Frontend: Next.js + Tailwind
Backend: FastAPI 
Database: PostgreSQL + Redis (session)
Vector DB: Pinecone
LLM: Claude API
Auth: Gmail OAuth (no Clerk yet)
Deployment: Vercel + Railway
```

## Success Metrics
- User can connect Gmail in <2 minutes
- System correctly identifies draft emails 
- Completed drafts match user's writing style (subjective review)
- Zero data leaks or auth issues
- 10 beta users complete full flow

## Key Risks & Mitigations
**Risk:** Gmail API complexity → **Mitigation:** Start with read-only, add compose later
**Risk:** Style matching accuracy → **Mitigation:** Simple template matching first, embeddings second
**Risk:** User trust → **Mitigation:** Show all changes, require approval

This focused scope gives you a working demo by week 3 with week 4 as buffer. The architecture naturally extends to Google Docs and other apps once the core pattern works.
